# StockFlow — заказы и склад

REST API небольшого магазина. Позволяет создать товар, оформить заказ на один вид товара и отменить заказ с возвратом остатка.

**Главная инженерная задача:** не продать больше товара, чем есть на складе, при одновременных HTTP-запросах. Списание выполняется условным UPDATE и сохраняется с заказом в одной транзакции. Повторная отмена не возвращает остаток второй раз.

## Запуск из корня репозитория

```powershell
docker compose -f projects/StockFlow/compose.yaml up --build -d
```

Swagger: [localhost:5101/swagger](http://localhost:5101/swagger). Готовность: [localhost:5101/health/ready](http://localhost:5101/health/ready).

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/products` | Создать товар |
| GET | `/api/products?page=1` | Товары, по 20 на страницу |
| GET | `/api/products/{id}` | Остаток и цена товара |
| POST | `/api/orders` | Создать заказ и списать остаток |
| GET | `/api/orders/{id}` | Статус заказа |
| POST | `/api/orders/{id}/cancel` | Отменить заказ |

Примеры: [requests.http](requests.http). Выполняйте запросы последовательно; если HTTP-клиент не поддерживает ссылки на именованные ответы, скопируйте полученные ID вручную.

Проверка: создайте товар с остатком 5, закажите 3 единицы, повторите заказ на 3 — получите 409. Отмените успешный заказ — остаток станет 5. Повторная отмена вернёт 409.


Без PostgreSQL конкурентный тест пропускается. Для его выполнения задайте `PORTFOLIO_TEST_DATABASE` по инструкции в корневом README. Модель упрощена: нет корзины, платежей и идемпотентного создания заказов.
